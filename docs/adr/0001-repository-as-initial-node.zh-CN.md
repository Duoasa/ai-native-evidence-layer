# ADR-0001：使用 Git 仓库作为初始协作节点

简体中文 | [English](0001-repository-as-initial-node.md)

状态：已接受
日期：2026-08-28

## 背景

长期设计是分布式的，但个人维护者需要一个透明、低成本，并支持审核、历史、可重复构建和 Fork 的起点。

## 决策

使用公开 Git 仓库作为第一个协作节点。源数据和 Schema 通过 Pull Request 审核，Git 记录目录变化历史，确定性制品由已提交文件生成。

仓库本身不是外部声明的证据；声明引用仍然负责来源证明。

## 考虑过的替代方案

- **先建托管数据库：** 动态查询更快，但在语义验证前引入运维成本和中心服务依赖；
- **先建自定义联邦：** 符合最终愿景，但过早引入身份、传输、信任和同步风险；
- **Wiki 页面：** 便于人类编辑，但不利于确定性机器契约。

## 后果

- 正面：开放审核、可 Fork、版本历史、低成本、可重复发布；
- 权衡：写入吞吐和实时性有限；
- 后续：首个试点成功后再定义独立节点发现。
