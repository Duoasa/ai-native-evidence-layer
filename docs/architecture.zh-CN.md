# 架构

简体中文 | [English](architecture.md)

## 职责分层

| 层级 | 负责 | 不得静默承担 |
|---|---|---|
| 发布者 | 来源声明与修订 | 独立核验 |
| 证据节点 | 标准化、引用和观测状态 | 普遍真理 |
| Schema | 可迁移语义与兼容性 | 领域排名策略 |
| 校验器 | 结构和确定性语义检查 | 人工来源判断 |
| 索引/聚合器 | 发现、投影和保留冲突的组合 | 擦除来源 |
| AI 消费者 | 查询规划、比较和解释 | 无标记地编造事实 |

## 初始仓库数据流

```text
试点源 JSON
    ↓ 校验
标准化实体与声明
    ↓ 确定性构建
dist/catalog.json + catalog.jsonl + node.json + changes.json
    ↓ 消费
AI 客户端、静态浏览器与独立校验器
```

初始 Git 仓库是透明的协作节点，不是最终联邦架构。Pull Request 提议修改，审核确定目录是否接受，Git 历史记录目录变化，而外部声明的证据仍然是其引用来源。

## 依赖方向

```text
Schema ← 校验库 ← CLI 脚本 ← CI
   ↑          ↑
示例       试点目录
```

领域试点可以依赖核心 Schema；核心 Schema 不得把某个试点词汇作为协议不变量。尚未标准化的扩展使用带命名空间的对象。

## 状态模型

- `asserted`：某来源提出声明，不暗示独立审核；
- `verified`：引用来源已按记录的方法审核；
- `disputed`：相关证据冲突或解释仍有争议；
- `stale`：观测时间超过领域时效政策；
- `withdrawn`：发布者或节点主动撤回；
- `unknown`：系统无法确定有支持的值。

缺少声明不等于否定声明；检索失败也不是不存在的证据。

## 未来联邦边界

联邦化需要稳定节点身份、Schema 版本协商、跨节点实体映射、冲突保留和制品来源认证。这些能力在首个试点验证声明模型前明确延期。
